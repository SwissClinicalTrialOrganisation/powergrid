The R-devel check ERRORs are from

90136 | hornik | 2026-06-12 09:14:40 +0200 (Fri, 12 Jun 2026) | 1 line
Have aperm.default() copy attributes as documented since 2006.

which brings aperm.default() in sync with both its docs and t.default().

This can change how apply() works on classed objects.  The code for
apply() first does

    if(is.object(X))
        X <- if(dl == 2L) as.matrix(X) else as.array(X)

and lateron

    newX <- aperm(X, c(s.call, s.ans))
    dim(newX) <- c(prod(d.call), d2)

and then calls the given function on the newX[, i] "column" slices.

When X is a classed object which does not get changed to a standard
matrix/array (as generated by matrix()/array()) and has no aperm()
method, the class (and the "other" attributes as per ?aperm) now get
copied, so that subsequently setting the dim may invalidate the object
if there is no appropriate dim<-() method, and/or newX[, i] now uses a
non-default subscript method which no longer works.

The simplest "fix" is to add an aperm() S3 method for the class which
drops attributes as aperm.default() previously did.  Alternatively, one
could also consider providing as.matrix()/as.array() methods which
change to standard matrix/array.
